## 2. 时间对应与轨迹连续性

|指标|A|B|
|---|---:|---:|
|同时刻 3D 距离|97.12|101.00|
|忽略顺序，预测点到同一未来 chunk 最近目标点的距离|56.59|62.17|
|同上，像素最近距离|52.93 px|58.77 px|
|预测相邻 horizon 点平均位移|66.19|65.44|
|示范相邻 horizon 点平均位移|7.69|7.69|

最近点距离允许多个预测点匹配同一个目标点，不保证覆盖整条轨迹，也不保证时间顺序，只作乐观诊断。其明显小于同时刻误差，解释了为什么点云范围相似而执行序列不准确。相邻位移约为示范的 8.5–8.6 倍，说明预测序列存在明显跳动；这不是实际机器人速度测量。

固定延迟检查：扫描 -30 至 +30 帧，比较 pred[t,h] 与 command[t+h+delta]。每个延迟使用完全相同的内部 anchor：30 <= t < N-59，h=0..29；因此此处零延迟值与全量分数不同。正 delta 表示拿更晚的目标比较。

- A：最佳 delta=-2 帧，112.46 -> 111.86 mm，仅改善 0.61 mm。
- B：最佳 delta=-3 帧，114.16 -> 113.15 mm，仅改善 1.01 mm。

结论：单一固定时间偏移解释不了主要误差。不能据此排除所有局部时间问题。固定示例（第一条验证 episode 第100帧）见 `time_order_example.png`；用逐坐标时间曲线显示三次采样的跳动，全量相邻位移统计支持该观察。尚未确定是训练不足、时序建模问题还是 Flow Matching 训练/采样实现问题。

## 下一步建议

优先检查“输出范围合理、时间序列却跳动”的原因：审查 Flow Matching 的训练与采样时间方向、噪声/速度定义和动作 horizon 对应关系；再用极少数训练片段做过拟合检查，验证能否恢复平滑且准确的动作序列。不要先通过换标定或单纯延长正式训练解释这些结果。另需后续核对实际状态与当前命令差异，但不在本次前三项诊断内。
